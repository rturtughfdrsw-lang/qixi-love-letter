# 七夕动态情书网站设计规格

## 1. 项目目标

在 `E:\七夕` 中制作一封送给郭静恬的七夕动态情书。网站不是普通长页面，而是一封按幕播放、由用户轻触推进的电子情书，同时具备私人回忆册的照片层次。

成品优先服务手机端，并兼容 iPhone Safari、Android Chrome、Windows Edge 与 Windows Chrome。网站使用原生 HTML、CSS、JavaScript 和 Web Animations API，不使用 React、Vue、大型框架或在线动画依赖。

## 2. 不可变内容规则

- `assets/七夕.txt` 是正文唯一来源；不复制正文到 JavaScript 中，不改写该文件。
- 正常正文文字不得润色、纠错、增删或替换。
- 可以按自然语义拆分段落、句子和动画节点，但用户最终看到的正文字符与顺序不变。
- `---` 只用于划分主要 Scene，不显示。
- 明确的开发说明、素材路径、配图标记和页面功能说明不显示，而是转换为网页行为。
- Markdown 标题符号、粗体符号只参与语义识别，不作为正文字符显示。
- “（好多好多）”属于正常正文，必须保留；该句末尾的 `09` 是礼物图片编号，不显示。
- `页面结束按钮` 以下的按钮解释、素材说明、末尾开发提示和“我们慢慢来。”不作为信件正文展示；它们用于生成最终菜单和交互。
- LAST PART 的正文、`To be continued... ♡`、落款“—— 爱你的 / 秦灿宇 / 2026 8.13”原样保留。

## 4. 场景结构

正文按 `---` 解析为主要块，再通过语义规则拆成以下 10 个播放阶段：

1. **开场**：暗色朦胧背景、关闭的信封、“给郭静恬宝宝的一封信”。点击信封后开始 BGM，信封打开，鲜花展开，少量粉色/奶白/淡玫瑰半透明气球上升，花瓣、星点和柔光进入，背景转为奶白浅粉，并显示“亲爱的郭静恬宝宝你好呀~”。
2. **我想对你说**：正文按句逐步出现，素材 01、03、04B 随对应句子进入。照片像夹进信纸或记忆卡片，不遮挡正文。
3. **daily-gifts**：礼物文字逐项出现，对应照片随后进入并重新组织画面；不使用九宫格。
4. **手工书**：先呈现“还有最让我最让我感动的...”，再逐段展开完整长文。右侧/下方为参差卡堆；点击顶层照片会滑出、移到底层，剩余卡片重排。移动端保持足够点击面积。
5. **谈未来**：氛围从手工书高潮稍微收束；素材 05 与“一个一个完成。一个一个打上勾。”形成轻量的圆点到勾选视觉，不创建独立愿望页面。
6. **你改变了我**：减少装饰和照片，扩大留白。“没事。”单独停留后以删除线/消散组合离开，但原文字仍先完整可见。“我想变成一个更会表达爱的人。”成为视觉重点。
7. **恋爱计时器**：正文和实时数字共同出现。开始时间集中配置为 `2026-06-10T00:00:00+08:00`；显示 `XXX 天` 与 `XX 小时 · XX 分钟 · XX 秒`，每秒按当前真实时间重新计算。
8. **偷拍、我爱你与照片高潮**：先保持可阅读的正文安全区，再从 `together` 中按批次从不同方向加入大小、旋转和景深不同的照片。“我爱你。”和“特别特别需要你”获得独立停顿；手机端照片永不覆盖正文。
9. **LAST PART**：逐渐减少照片和运动，背景回归干净信纸。原样显示 LAST PART、`To be continued... ♡`、落款和日期。
10. **最终菜单**：只显示“↻ 再放一遍”“♡ 郭静恬美照”“📷 我们的照片”三个按钮。

## 5. 播放和状态模型

应用使用单一场景控制器维护：

- 当前 Scene 索引
- 当前 Scene 的内部阅读拍点
- 是否处于开场、转场、播放或等待用户状态
- 已创建动画实例及清理函数
- 手工书卡片顺序
- together 高潮已渲染照片集合
- 当前相册及灯箱状态

每幕进入后，文字和图片按时间线连续出现。动画结束才显示轻量 `♡ 轻触继续`。推进时暂时锁定输入，避免连点跨越多个 Scene。支持主继续按钮、场景空白安全区域点击、键盘 Enter/Space；照片卡、音乐按钮、相册按钮和灯箱区域阻止冒泡，避免误推进。

较长场景内部使用多个阅读拍点：已读文字柔和退到次级位置或换位，新文字和照片接续出现。正常手机尺寸不依赖长页面滚动；极矮屏允许场景正文区域少量纵向滚动作为安全兜底。页面绝不产生横向滚动。

“再放一遍”执行软复位：停止并清理动画、回到开场、关闭信封、恢复手工书初始顺序、移除临时照片、关闭相册/灯箱、复位场景和文字状态。BGM 使用同一个 `Audio` 实例，暂停并将播放位置归零，不创建第二实例。

## 6. 动画语言

- 开场：暗到亮、信封展开、花朵生长、气球慢速上升、柔光扩散。
- 正文：逐句上浮、模糊变清、局部逐字、信纸轻呼吸；根据句长与情绪选择，不统一套用同一个效果。
- 照片：从侧后方进入、轻微旋转后落定、景深由虚到实、错层重新排列。
- 礼物：每项有自己的进入方向/展开细节，但保持同一速度和阴影语言，不使用夸张弹跳。
- 手工书：顶层卡片滑出并回到底层，卡堆位置和阴影同步重排。
- “没事。”：完整显示、停顿、删除线扫过、文字消散。
- 计时器：变化数字轻微上跳或翻页，不让整个数字块抖动。
- together 高潮：分批加入照片，每批数量受性能预算限制；LAST PART 进入时逐渐退出。
- 转场：当前幕柔和退场后下一幕进入，转场期间禁止输入。
- `prefers-reduced-motion: reduce` 时缩短或取消位移、漂浮和景深动画，但保留内容顺序和可操作性。

## 7. 视觉系统与响应式设计

核心配色为奶白、浅粉、柔和玫瑰色、少量深粉和暖黑正文。背景有低对比纸张/雾面层次，不使用满屏红心、廉价霓虹、强发光字或婚庆模板式装饰。

字体优先使用系统可用的中文衬线字体呈现信件气质，界面按钮使用清晰的系统无衬线字体；不依赖在线字体。正文在手机端保持舒适字号和行高。

所有主要容器考虑 `env(safe-area-inset-*)`。手机端采用单列安全阅读区；桌面端使用有限宽度的双区域构图，不把手机版无限拉宽。照片使用固定比例容器和 `object-fit`，避免布局跳动。

## 8. 相册设计

两个相册均作为全屏覆盖层打开，与主信件视觉一致，不离开应用状态：

- “郭静恬美照”使用 3 张真实照片组成大幅拍立得/错层展台，而非普通九宫格。
- “我们的照片”使用 20 张真实照片组成响应式 Masonry 风格回忆墙。
- 点击照片打开灯箱；支持前后浏览、关闭、键盘方向键/Escape 和触摸滑动。
- 缩略图 `loading="lazy"`、`decoding="async"`；灯箱只优先加载当前及相邻照片。
- 关闭相册后返回最终菜单，不重置主信件。

## 9. BGM

首次点击开场信封时创建或复用唯一音频实例并调用播放，满足浏览器用户手势要求。BGM 循环，默认适中音量，并通过短时间渐增实现淡入。

右上角音乐按钮始终保持小而可点击，显示播放/暂停状态并提供可访问标签。播放失败、文件不存在或浏览器拒绝时只更新按钮状态并记录诊断信息，不阻塞场景系统。

## 10. 正文解析与数据流

通过本地 HTTP 服务加载 `assets/七夕.txt`：

1. `fetch` 获取 UTF-8 原文。
2. 以独占一行的 `---` 切分原始块。
3. 识别开场说明、配图标记、daily-gifts 编号、手工书提示、计时器提示、together 提示和页面结束说明。
4. 从可见正文中移除开发标记，但保留正常括号文字和原始标点。
5. 输出 Scene/Beat 数据；素材路径全部使用项目相对路径。
6. 场景控制器消费数据并创建 DOM 与动画。

如果正文请求失败，页面显示“正文加载失败”和本地服务器启动提示，音乐和其他错误不能使页面白屏。由于浏览器对 `file://` 下 `fetch` 的限制，正式预览通过本地 HTTP 服务打开。

- `content.js`：配置、素材清单、正文读取和解析。

- `main.js`：初始化与模块协调。
- `style.css`：视觉系统、全部场景、动画和响应式规则。

## 12. 性能与可靠性

- 当前 Scene 才运行动画；离场后取消动画和计时任务。
- 仅预加载下一幕必要图片。
- together 高潮只分批挂载有限照片；完整 20 张只在用户打开相册后懒加载。
- 对大图提供明确尺寸/比例容器，避免 layout shift。
- 不压缩、不覆盖、不重命名用户原始照片。
- 计时器每秒更新，离开计时场景后可降低更新频率或停止显示更新；重新进入时按真实当前时间计算。
- 页面不可见时暂停纯装饰动画；恢复可见时重新同步状态。

## 13. 验证与验收

### 自动验证

- 正文解析测试：可见正文与去除开发标记后的原文逐字符一致。
- Scene 数量、素材映射、daily-gifts 01–10、手工书 7 张、个人照片 3 张、together 20 张断言。
- 恋爱计时器基于固定时间的天/时/分/秒计算测试。
- 重播复位、手工书循环顺序和 BGM 单实例测试。
- 所有 HTML 中的本地资源路径存在性检查。

### 浏览器验证

- 启动本地服务器，在桌面 Chromium 中实际走完开场、10 个阶段、三个按钮、两个相册和重播。
- 检查控制台错误、网络 404、图片解码失败和 BGM 播放状态。
- 使用手机视口检查无横向滚动、正文无遮挡、按钮触控区域、刘海安全区、计时器不溢出、手工书可点击。
- 检查窄屏、矮屏、桌面宽屏和 `prefers-reduced-motion`。
- 如本机无法直接运行 Safari，使用符合标准的实现并明确报告 Safari 需在目标设备进行最终真机确认。

## 14. 明确不做

- 不制作独立的“我们一起做的事”页面。
- 不添加“写给未来的我们”、留言板、登录、后台、数据库或用户系统。
- 不增加第四个结尾按钮。
- 不使用项目绝对路径写入网页代码。
- 不修改正文和原始照片。
